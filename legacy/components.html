Buttons & links

One primary action per view. Minimum target 44px; funnel controls are 48px because they are used with a thumb on a moving boat.

Never put flex-1 on a button that has an explicit height inside a container that is flex-col at any breakpoint. In a column, flex-basis governs the height and takes precedence over h-14, so the button collapses to content height. For a pair of buttons that sit side by side on one row and stack on another, use grid gap-3 sm:grid-cols-2 — grid never touches the main-axis size, so the height holds at every width.

Layout & overlays

Sticky header

The header sticks at every width. Its Alpine wrapper carries class="contents" — without it the wrapper generates a ~116px box and, because a sticky element is constrained to its containing block, the header would unstick immediately. Past 72px of scroll, layout.js sets data-compact="true" and the bar shortens from 80px to 64px with a solid background and a shadow.

Reveal on scroll

One IntersectionObserver gives every main > section a 0.7s fade and 16px rise, once. The hidden state is only ever added by JavaScript, so with JS off nothing is invisible; sections already on screen are marked visible in the same tick, so the hero never animates. Reduced-motion and the three funnel screens opt out entirely — the funnels already animate their steps, and stacking the two reads as a stutter.

Where the CSS comes from

Tailwind is compiled by the CLI, not the browser. Tokens live in tailwind.config.js; the output is assets/css/tailwind.css, loaded before app.css so the hand-written file keeps the last word. Fonts and Alpine are local too — the build fetches nothing from a third-party origin.

Add a class in markup and you must rebuild. A class with no rule fails silently — nothing throws, the element just looks wrong. Run npm run css:watch while working on the design, and npm run qa before handing anything over; the fourth check rebuilds the CSS and compares it byte-for-byte with the committed file.

The scan covers *.html, partials/*.html, data.js and layout.js. The two JS files are on that list because the card renderers and the toast build their markup as template strings — leave them out and every card compiles unstyled.

Integration contract

The full field-by-field version lives in docs/HANDOFF.md. These are the rules that apply everywhere.

Never render

  • undefined, null, NaN or [object Object]
  • A price without a currency, or a formatted price stored as a string
  • A raw API error, status code or stack trace
  • An unknown enum value passed straight through to the UI
  • An empty collection as a blank area with no explanation

Always provide

  • A fallback string for every optional field — “On request”, “—”
  • Integer minor-unit-free USD for prices; the client formats
  • ISO YYYY-MM-DD for dates, never a localised string
  • A stable slug or id on every record, used in the URL
  • A reference code on every submitted form, shown to the guest
